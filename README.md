# gosling

<p align="center">
  <img src="assets/gosling.svg" alt="gosling mascot" width="230">
</p>

gosling adds some TypeScript syntax to Go. Write `.gol` files. gosling converts each one to a plain, gofmt-formatted `.go` file in the same directory.

```go
func Load(path string) (Config, error) {
	let cfg: Config
	try {
		const data = os.ReadFile(path)
		json.Unmarshal(data, &cfg)
	} catch (e) {
		return Config{}, fmt.Errorf("load: %w", e)
	}
	return cfg, nil
}
```

Features:

- `try` / `catch` / `finally` and `throw`, with typed catch clauses: `catch (e: *fs.PathError)`, `catch (e is fs.ErrNotExist)`
- `catch panic` for panics
- `try` expressions: `try strconv.Atoi(s) catch 0`
- Template literals: `` t`hello ${name}` ``
- Destructuring: `const {Name: name, Port} = cfg`, `let [first, ...rest] = xs`
- `let` and `const` declarations: `let n = 0`, `let names: []string`, `const data = os.ReadFile(path)`
- Parameter types after a colon: `func f(a: int, b: string): bool`
- `for (const x of xs)`, `for (const k in m)`, and `for (let i = 0; i < n; i++)`
- Optional chaining and `??`: `user?.Profile?.Name ?? "anon"`
- Arrow functions: `x => x * 2`, `(a, b) => a + b`
- Array methods on slices and arrays: `nums.filter(n => n%2 == 0).map(n => n * n)`
- Map methods: `ages.has(name)`, `ages.get(name) ?? 0`, `ages.keys()`
- Union types with exhaustive switches: `type Shape = Circle | Square`
- Struct shorthand and spread: `User{name, age}`, `[...a, ...b]`, `Point{...p, X: 5}`

## Why

I like Go, but I do not like to write `if err != nil` after every call. I know that this pattern is intentional in Go. But I think that it is too much on every call, and it makes a lot of repeated code.

I started with `try` / `catch`. Then I added other TypeScript features that I like.

Most of the Go community will probably not like this. gosling is a proof of concept, not a recommendation for everyone.

## Quick start

1. Install gosling:

   ```sh
   go install github.com/zacharyhill/gosling/cmd/gosling@latest
   ```

2. Rename the `.go` files that gosling will own to `.gol`. Then generate from the module root:

   ```sh
   find . -name '*.go' -not -path './vendor/*' -exec sh -c 'mv "$1" "${1%.go}.gol"' _ {} \;
   gosling ./...
   ```

3. Commit the `.gol` files and the generated `.go` files. Builds do not need gosling.

4. In CI, fail when generated files are out of date:

   ```sh
   gosling -check ./...
   ```

5. Optional: hide generated files in VS Code. Add this to `.vscode/settings.json`:

   ```json
   {
     "files.exclude": {
       "**/*.go": { "when": "$(basename).gol" }
     }
   }
   ```

6. Optional: add a `.gitattributes` file for GitHub. The first line collapses generated files in diffs. List the directories that gosling owns. The second line highlights `.gol` files as Go.

   ```gitattributes
   backend/**/*.go linguist-generated=true
   *.gol linguist-language=Go
   ```

Edit only `.gol` files. Run `gosling ./...` after each change.

## Usage

```sh
gosling              # convert .gol files in the current directory
gosling ./...        # include subdirectories (skips testdata, vendor, and . and _ directories)
gosling -check ./... # exit 1 if a generated file is out of date
gosling -lines=false # do not add line directives
gosling -v ./...     # show progress for each directory
gosling -version     # print the gosling version
```

To use `go generate`, add `//go:generate gosling` to a `.go` file in the package.

`foo.gol` becomes `foo.go`. `foo_test.gol` becomes `foo_test.go`. Generated files start with `// Code generated by gosling`. gosling does not overwrite a `.go` file that has no such header.

If you rename or delete `foo.gol`, gosling deletes the old `foo.go` on the next run. `gosling -check` reports the old file and does not delete it.

`examples/config` has a program and its generated output.

## Editor support

`editors/vscode` has a VS Code extension. It highlights `.gol` files and starts the gosling language server. It also gives `.gol` files their own language ID, so the Go extension does not report errors in them. Other editors can also use the language server. See [Other editors](#other-editors).

The language server is `gosling lsp`. It runs gopls on the generated code and maps each position back to the `.gol` file. It supports:

- Go to Definition (Ctrl+click), Go to Type Definition, and Go to Implementations
- Find All References and highlights
- Hover
- Completion and signature help
- Rename
- The outline of a file
- Diagnostics: gosling errors, and gopls warnings for the generated code

The server uses the text in the editor. When you save a `.gol` file, the extension writes the generated `.go` files of its package, as `gosling` does. When you rename or delete a `.gol` file in VS Code, the extension also deletes its old `.go` file. To stop this, set `gosling.generateOnSave` to `false`. A package with gosling errors keeps its old `.go` files.

### Install the extension

The extension is not on the Marketplace. You need Go and VS Code. Run these commands:

```sh
go install github.com/zacharyhill/gosling/cmd/gosling@latest
go install golang.org/x/tools/gopls@latest
curl -fLO https://github.com/zacharyhill/gosling/releases/latest/download/gosling.vsix
code --install-extension gosling.vsix
```

Then run **Developer: Reload Window** in VS Code. In Windows PowerShell, type `curl.exe`, not `curl`.

To build the extension from a clone of this repository, you also need Node.js:

```sh
go install ./cmd/gosling
go install golang.org/x/tools/gopls@latest
cd editors/vscode
npm install
npm run package
code --install-extension gosling.vsix
```

The extension runs on the machine that has your code. With Remote-SSH, open the remote folder first. Then run **Extensions: Install from VSIX...** and select `gosling.vsix`. VS Code then installs it on the remote machine.

If VS Code cannot find `gosling` or `gopls`, set `gosling.path` and `gosling.goplsPath` to the full paths. The server restarts when you change a gosling setting.

The first requests can be slow. gopls loads and type-checks the workspace when it starts. After that, requests are fast.

If the server does not start, open the Output panel (Ctrl+Shift+U) and select **gosling**. The panel shows the server errors.

### Other editors

An editor with an LSP client can run `gosling lsp`. The server uses standard input and output. It finds `gopls` in your `PATH`. These flags are available:

- `-gopls path` sets the gopls command.
- `-generate-on-save` writes the generated `.go` files of a package when you save one of its `.gol` files.

Give `.gol` files their own file type, not the Go file type. Otherwise a Go plugin reports errors in the gosling syntax.

#### Neovim

Neovim 0.11 and later have the LSP configuration built in. Add this to your `init.lua`:

```lua
vim.filetype.add({ extension = { gol = "gol" } })
vim.api.nvim_create_autocmd("FileType", {
  pattern = "gol",
  callback = function(args)
    vim.bo[args.buf].commentstring = "// %s"
  end,
})

vim.lsp.config("gosling", {
  cmd = { "gosling", "lsp", "-generate-on-save" },
  filetypes = { "gol" },
  root_markers = { "go.mod", ".git" },
})
vim.lsp.enable("gosling")
```

To highlight `.gol` files as Go, create the file `~/.config/nvim/syntax/gol.vim` with this line:

```vim
runtime! syntax/go.vim
```

With Neovim 0.10, use [nvim-lspconfig](https://github.com/neovim/nvim-lspconfig). Replace the `vim.lsp.config` and `vim.lsp.enable` lines with:

```lua
local configs = require("lspconfig.configs")
if not configs.gosling then
  configs.gosling = {
    default_config = {
      cmd = { "gosling", "lsp", "-generate-on-save" },
      filetypes = { "gol" },
      root_dir = require("lspconfig.util").root_pattern("go.mod", ".git"),
    },
  }
end
require("lspconfig").gosling.setup({})
```

Most Neovim commands that rename or delete a file do not tell the server. After such a change, run `gosling ./...` to remove the old `.go` file.

### Language server limitations

- Code that gosling generates, such as `try` and `catch`, has no hover or definition.
- A definition in generated code, such as a catch variable, goes to the nearest token before it.
- A rename fails if the name also occurs in code that gosling generates, such as a catch variable. A partial rename would break the code.
- Formatting is not supported. It would change generated code.
- After a syntax error, the server keeps the last version that parsed. Lines that changed since that version get no results until the file parses again. Type errors do not have this problem.

## Language

### try / catch

In a try block, gosling checks each call whose last result is `error`. A failure jumps to the catch block.

| You write       | Output                                                |
| --------------- | ----------------------------------------------------- |
| `f()`           | `if err := f(); err != nil { e = err; goto catch_N }` |
| `const x = f()` | `x, err := f()`, then `if err != nil { ... }`         |
| `x = f()`       | `x, e = f()`, then `if e != nil { goto catch_N }`     |
| `x += f()`      | `val, err := f()`, then a check, then `x += val`      |

If a call is a value, such as `f()` in `g(f())`, gosling moves it into a new checked statement. The new statement comes before the original statement:

```go
const n = strconv.Atoi(strings.TrimSpace(s)) * 2

val, err := strconv.Atoi(strings.TrimSpace(s))
if err != nil { ... }
n := val * 2
```

A call that returns `(A, B, error)` moves if it is the only argument of a call or the only result of a `return`. For example, `g(f())` becomes `val, val2, err := f()`, a check, and `g(val, val2)`.

The moved call runs before other calls to its left. Moved calls run in the order of the original expression. In an `if` or `switch` with an init statement, such as `if let x = g(); x > f(x) {`, a call from the condition runs after the init statement. The output then puts the init statement, the moved call, and the statement in a new block.

A call that runs only on some paths moves into a new `if` statement. So short-circuit evaluation does not change:

```go
if ok && strconv.Atoi(s) > 0 {

cond := ok
if cond {
	val, err := strconv.Atoi(s)
	if err != nil { ... }
	cond = val > 0
}
if cond {
```

- For a call on the right side of `&&` or `||`, the whole operation moves before the statement, as above.
- A loop condition with a checked call moves into the loop body. It runs before each iteration. If it is false, `break` ends the loop.
- An `else if` with a checked call becomes `else { ...checks...; if ... }`.
- A `case` expression with a checked call splits the switch. The cases from that case on go into a nested switch in a `default` case. The checks go before the nested switch. gosling puts the switch tag in a variable, so the tag runs one time.

These calls are errors:

- a call in a `??` default or after `?.`
- a call in the post statement of a `for` loop
- a call in a later expression of a `case`, such as `f()` in `case a, f():`
- a call in a `case` after the `default` case, or in a `case` that the case before it enters with `fallthrough`

Rules:

- Checks apply in nested `if`, `for`, `switch`, and `select` bodies. They do not apply in function literals.
- gosling also checks a call in the init statement of an `if`, `switch`, or `for`, such as `if let n = f(); n > 0 {`. The check runs before the condition. The output puts the init statement, its check, and the statement in a new block. This also works in an `else if`.
- Outside a try block, an assignment such as `x = f()` must receive the error, as in Go. Otherwise gosling reports an error.
- gosling does not change a call that already receives its error, such as `const n, err = f()`.
- gosling checks all calls that return an error, including `Close()` and `fmt.Fprintf`. To skip a check, write `_ = c.Close()`.
- Only the last result counts. A call such as `func f() (error, int)` used as a statement is an error.
- A last result of a pointer or interface type that implements `error`, such as `*MyError`, also counts. gosling compares the typed result with nil before it puts the result in the catch variable. So a nil `*MyError` is not a failure. Other types that implement `error`, such as `type Code int`, do not count, because they cannot be nil.
- `catch { ... }` without a variable is allowed.
- Try blocks can be nested. A failure in a catch block goes to the outer try.
- If the try block always ends in `return`, `break`, `continue`, `goto`, `panic`, or a call that never returns, gosling does not add a jump over the catch block.
- A function whose try and catch both return needs no last `return`.
- Some calls never return: `t.Fatal`, `t.FailNow`, `t.Skip`, `os.Exit`, `runtime.Goexit`, `log.Fatal`, and `log.Panic`, with their variants. When a function ends in a try, these calls end it.
- If no call in the try block can fail, gosling removes the catch block.
- The catch variable can have the same name as a variable in the try block.
- There is no `?` operator. Use try / catch.

The output uses labeled blocks and `goto`, not closures. So `return`, `break`, and `continue` work as in Go:

```go
{
	var e error
	{
		// try body
	}
	goto end_N
catch_N:
	{
		// catch body
	}
end_N:
}
```

### Typed catch

A catch clause can catch only some errors. gosling tests the clauses in order. The first clause that matches runs.

```go
try {
	const data = os.ReadFile(path)
	return parse(data)
} catch (e: *fs.PathError) {
	return t`cannot read ${e.Path}`
} catch (e is fs.ErrNotExist) {
	return "missing"
} catch (e) {
	return e.Error()
}
```

- `catch (e: T)` uses `errors.As`. `e` has the type `T`. `T` must implement `error` or be an interface.
- `catch (e is value)` uses `errors.Is`. `e` is the error.
- Only the last catch can catch all errors, with `catch (e)` or `catch`. This catch is optional.
- Without it, an error that no clause matches goes to the outer try. The finally block of this try runs first. If no outer try exists, the function returns the error. Then the last result of the function must be `error`, and the other results get their zero values.
- Each catch must be on the same line as the closing brace before it.
- A catch type must be on one line.

### try expressions

`try call catch fallback` gives the value of the call. If the call fails, it gives the fallback. gosling discards the error.

```go
const port = try strconv.Atoi(s) catch 8080

port := func() int {
	if v, err := strconv.Atoi(s); err == nil {
		return v
	}
	return 8080
}()
```

- The call must return exactly a value and an `error`.
- Only the error of the call counts. In a try block, a failing call in its arguments goes to the catch block, as usual.
- The fallback runs only if the call fails. It must have the type of the value.
- The fallback continues to the end of the expression, such as a `,`, a `)`, or the end of the statement. Use parentheses to end it earlier: `(try f() catch 0) + 1`.
- A fallback can be another try expression: `try a() catch try b() catch 0`.
- The fallback cannot read the error. `catch (e) => ...` is an error. Use a try statement.
- `try` starts a try expression only if `catch` follows in the same expression. Otherwise `try` is an identifier.

### finally

The finally block runs after the try or catch block. It runs on every exit: the end of the block, `return`, `break`, `continue`, `goto`, or a failure that an outer try catches. It does not run on a panic, unless the try statement has a `catch panic` clause.

- gosling evaluates return values before the finally block runs.
- A `return` in the finally block replaces the pending return.
- Nested finally blocks run from the inside out.
- In a try with no catch, a failure goes to the outer try after the finally block runs.

### throw

`throw` sends an error to the catch block, as a failing call does:

```go
try {
	const n = strconv.Atoi(s)
	if n < 0 {
		throw fmt.Errorf("negative: %d", n)
	}
	return n, nil
} catch (e) {
	return 0, fmt.Errorf("parse %q: %w", s, e)
}
```

- In a try block, `throw err` sets the catch variable and jumps to the catch block. The finally blocks between them run first.
- In a catch block, `throw` goes to the outer try. So `throw fmt.Errorf("load: %w", e)` rethrows a wrapped error.
- If no try block catches the error, the function returns it. The last result of the function must be `error`. The other results get their zero values. So `throw err` in `func f() (int, error)` becomes `return 0, err`.
- In other functions, `throw` without a try block is an error.
- The value must be an `error`.
- `throw` is a keyword only at the start of a statement, before a value on the same line. So `throw(x)` and `throw = x` use an identifier named `throw`.

### catch panic

A `catch panic` clause catches a panic in the try block. It comes after the catch block, or directly after the try block:

```go
try {
	process(job)
} catch (e) {
	log.Print(e)
} catch panic (p) {
	log.Print("panic: ", p)
} finally {
	job.Done()
}
```

The variable has the type `any`. It holds the value that `recover` returns. `catch panic { ... }` without a variable is also allowed.

- With `catch panic`, the finally block also runs after a panic in the try block.
- `catch panic` catches only panics in the try block. A panic in a catch block or in the catch panic block goes up, as in Go.
- gosling puts the try block in a function literal with a deferred `recover`. `return`, `break`, `continue`, and `goto` work as in Go. The function literal records the exit and returns. The code after the function literal then does the exit.
- `defer` directly in the try block is an error. It would run at the end of the try block, not at the end of the function. A `defer` in a function literal in the try block is allowed.
- `runtime.Goexit`, `t.Fatal`, and `os.Exit` are not panics. `catch panic` does not stop them.
- Before Go 1.21, `catch panic` does not catch `panic(nil)`.
- `catch panic` cannot follow a typed catch clause.

### Template literals

`` t`...` `` becomes a `fmt.Sprintf` call. The verb comes from the type of each `${expr}`:

- `%s` for strings, `%d` for integers, `%t` for booleans
- `%v` for other types, and for types with methods such as `time.Duration` and errors
- Floats use `strconv.FormatFloat(x, 'f', -1, 64)`, so `1000000` does not print as `1e+06`

```go
const msg = t`hello ${u.Name}, you are ${u.Age}` // fmt.Sprintf("hello %s, you are %d", u.Name, u.Age)
```

JavaScript escapes work, such as `\n`, `\t`, `\xHH`, `\uHHHH`, and `\u{H...}`. Write `\${` for a literal `${`. A template cannot contain a backtick. gosling adds the `fmt` and `strconv` imports if necessary.

### Destructuring

```go
const {X, Y: y} = p             // X, y := p.X, p.Y
const [a, b] = pair             // a, b := pair[0], pair[1]
let [first, _, ...rest] = xs    // first, rest := xs[0], xs[2:]
const {Addr: {Host}} = cfg      // Host := cfg.Addr.Host
const [[a, b], c] = rows        // a, b, c := rows[0][0], rows[0][1], rows[1]
const {Name: name} = load(path) // tmp := load(path); name := tmp.Name
{X, Y} = p                      // X, Y = p.X, p.Y
```

A name can have a default value:

```go
const {Port = 8080, Timeout = 30} = cfg
const [first = "-"] = args
```

- In an object pattern, the default applies if the field has its zero value, such as `0`, `""`, or `nil`. The field type must be comparable or able to be nil.
- If a pointer field has a default of its element type, the result is the value that the pointer points to, as with `??`. So `Timeout = 30` with `Timeout *int` gives an `int`.
- In an array pattern, the default applies if the index is past the end of the slice. An element without a default still panics past the end. A nested element can have a default too, such as `const {Addr: {Port = 80}} = cfg`.
- gosling evaluates the default only if it applies. The default must be plain Go. Assign gosling syntax, such as a template literal, to a variable first.

`let` and `const` declare new names. Code cannot assign to the names that `const` declares. Without `let` or `const`, the pattern assigns to existing variables. Declare names with a pattern only in functions. A pattern can use more than one line and can have a trailing comma.

Patterns can be nested. Put an object or array pattern where a name can go. A rest element can only be the last element of an array pattern.

Field names must match exactly. gosling evaluates a complex right side one time, into a temporary. An index past the end of a slice panics, as in Go. gosling does not read the index of a `_` element, so `const [a, _] = xs` does not panic if `xs` has one element.

An array pattern can also take the results of a call. This applies if the call has two or more results, not counting a last `error`:

```go
const [n, name] = parse(s) // n, name := parse(s), with parse returning (int, string, error)
```

In a try block, gosling checks the error. A `_` element skips a result. A pattern with a rest element, a nested pattern, or a default cannot take results.

A parameter can also be a pattern. gosling gives the parameter a name and declares the names at the start of the body:

```go
func handle({Name, Port}: Config) { // func handle(config Config) { Name, Port := config.Name, config.Port
configs.map(({Name}) => Name)       // func(arg Config) string { Name := arg.Name; return Name }
```

- The parameter name comes from the type. `Config` and `*pkg.Config` give `config`, and `HTTPConfig` gives `httpConfig`. Other types give `arg`. If the file already uses the name, gosling adds a number.
- In a function declaration or a function literal, write the type after the pattern. An arrow parameter without a type gets its type from the context.
- A pattern parameter fits both parameter orders. The other parameters follow the order rule, so `func f({X}: P, n: int)` and `func f({X}: P, n int)` both work.
- A pattern parameter can be nested and can have defaults.

### let and const

In `.gol` files, declare variables with `let` and `const`. `:=` is an error. `var` in a function is an error. Package-level `var` is allowed, because `let` has no grouped form.

```go
let count = 0                  // count := 0
let names: []string            // var names []string
let port: int64 = 8080         // var port int64 = 8080
const data = os.ReadFile(path) // data := os.ReadFile(path)
const limit = 10               // const limit = 10
const scale: float64 = 1.5     // const scale float64 = 1.5
```

At package level, `let x = v` becomes `var x = v`.

A `const` with a constant value stays a Go constant. A `const` with a different value becomes a variable. gosling reports an error if code assigns to this variable, increments it, or uses it as a `range` target. Code can change its fields, its elements, and the value it points to, as in TypeScript.

The header of an `if`, `for`, `switch`, or `case` can also start with `let` or `const`. Both become `:=`:

```go
for (let i = 0; i < n; i++) {   // for i := 0; i < n; i++ {
for const k, v = range m {      // for k, v := range m {
if let v, ok = m[key]; ok {     // if v, ok := m[key]; ok {
switch const s = shape.(type) { // switch s := shape.(type) {
case let msg, ok = <-ch:        // case msg, ok := <-ch:
```

- `let` needs a type, a value, or both.
- The guard of a type switch after an init statement can also use `let` or `const`: `switch let v = f(); const s = v.(type) {`.
- A header declaration cannot have a type. Write `let i = int64(0)`, not `let i: int64 = 0`.
- Code cannot assign to a name that `const` declares in a header.
- `const ( ... )` groups are plain Go. Their values must be constant.

### Parameter types

Parameters and results can put the type after a colon, as `let` does:

```go
func parse(text: string, base: int): (int, error) // func parse(text string, base int) (int, error)
func (u: *User) Rename(name: string): string      // func (u *User) Rename(name string) string
let isEven: func(n: int): bool                    // var isEven func(n int) bool
const add = (a: int, b: int) => a + b             // add := func(a int, b int) int { return a + b }
```

- Go order also works. So Go code that you copy into a `.gol` file stays valid.
- A function uses one order. If a parameter or the result has a colon, all parameters and named results must have a colon. Write `a: int, b: int`, not `a, b: int`.
- In that order, the result type comes after `):`, as in `func f(): int`.
- The receiver can use either order.
- The rules apply to function declarations, function literals, arrow functions, function types, and interface methods.

### for...of and for...in

`for (const x of xs)` becomes `for _, x := range xs`. For a channel, an integer, or an `iter.Seq`, it becomes `for x := range xs`. `for (const k in m)` becomes `for k := range m`. `let` also works. With `const`, gosling reports an error if the loop body assigns to the variable.

A `for...of` loop can destructure each element. gosling declares the names at the start of the loop body:

```go
for (const {Name, Port} of configs) { // for _, tmp := range configs { Name, Port := tmp.Name, tmp.Port
for (const [k, v] of pairs) {         // for _, tmp := range pairs { k, v := tmp[0], tmp[1]
```

A pattern in a `for...in` loop is an error. To read the keys and values of a map, use `for const k, v = range m`.

`for (let i = 0; i < n; i++)` becomes `for i := 0; i < n; i++`.

### Optional chaining and ??

`a?.b` reads `b` only if `a` is not nil. If a link is nil, gosling skips the rest of the chain and gives the zero value. The left side of `?.` must be a pointer or an interface. A type parameter is allowed only if each type in its constraint can be nil, as in `[P *User]`.

`x ?? d` gives `d` if `x` is nil or its chain was skipped. If `x` is a pointer and `d` has the element type, gosling dereferences `x`. So `cfg.Port ?? 8080` with `Port *int` gives an `int`. This also applies to a type parameter whose types are all pointers to the same type, as in `[P *int]`.

These are errors:

- a left side of `??` that cannot be nil, such as a type parameter with constraint `any`
- `??` mixed with `||` or `&&` without parentheses
- the address of an optional chain, such as `&a?.b`
- an optional chain that is assigned to or incremented, such as `a?.b = c` or `a?.n++`
- a dereference of an optional chain, such as `*a?.p`. To read the value, use `a?.p ?? d`.

gosling evaluates each link one time:

```go
const name = user?.Profile?.Name ?? "anon"

name := func() string {
	if v := user; v != nil {
		if v := v.Profile; v != nil {
			return v.Name
		}
	}
	return "anon"
}()
```

The Go compiler inlines these function literals. A chain used as a statement, such as `conn?.Close()`, becomes an `if` statement.

### Arrow functions

```go
const double = (x int) => x * 2          // func(x int) int { return x * 2 }
sort.Slice(xs, (i, j) => xs[i] < xs[j])  // func(i int, j int) bool { ... }
let inc: func(int) int = x => x + 1
```

A parameter without a type gets it from the context:

- an array method callback
- a function argument, including generic functions such as `slices.SortFunc`
- a variable or assignment with a function type
- a `return` in a function that returns a function type
- an element of a composite literal, such as `[]func(string) bool{s => s != ""}`, a map value, or a struct field
- the first use of the variable that the arrow declares in a function

The first use of the variable is the first one in the source. If it is a call, each parameter gets the type of its argument. An untyped constant gets its default type. Other uses give their context, as above:

```go
const inc = x => x + 1                // func(x int) int { ... }
const answer = inc(41)
const bad = inc(1.5)                  // error: cannot use 1.5 as int value

const shout = s => strings.ToUpper(s) // func(s string) string { ... }
const loud = names.map(shout)
```

gosling does not use the body to find parameter types. Without a context, add types. The result type comes from the context or from the body. If the context has no result, an expression body becomes a statement. So `names.forEach(n => fmt.Println(n))` works.

`nil` has no type. If the body returns only `nil` for a result, the type must come from the context, as in `let f: func() error = () => nil`.

A package-level `const` can hold a generic arrow. It becomes a generic function:

```go
const identity = <T>(x T) => x                        // func identity[T any](x T) T { return x }
const keys = <K comparable, V>(m map[K]V) => { ... } // func keys[K comparable, V any](m map[K]V) []K { ... }
```

- Write the type parameters as in Go, between `<` and `>`. If the last type parameter has no constraint, it gets `any`. So `<K, V>` becomes `[K, V any]`.
- The parameters must have types.
- The result type comes from the body. So a generic arrow cannot call itself.

To declare the result types, write them after `):`. Use `name: type` for the parameters, as in [Parameter types](#parameter-types):

```go
const label = (n: int): string => strconv.Itoa(n)  // func(n int) string { ... }
const parse = (s: string): (int, error) => {        // func(s string) (int, error) { ... }
	return strconv.Atoi(s)
}
sort.Slice(xs, (i, j): bool => xs[i] < xs[j])      // func(i int, j int) bool { ... }
```

- A parameter without a type gets its type from the context. So `(i, j): bool` is valid.
- Give all parameters a type, or give no parameter a type. `(a: int, b): bool` is an error.
- Go order is an error with a result type. Write `(x: int): string`, not `(x int): string`.
- The parameters must be in parentheses. Write `(x): int => x`, not `x: int => x`.
- A declared result type has priority over the body. So `(): any => 1` returns an `any`.
- In `{f(a): x => x}`, `f(a)` is a call, so `x => x` is an arrow without a result type.

### Array methods

Slices and arrays have `map`, `filter`, `reduce`, `forEach`, `find`, `findIndex`, `findLast`, `findLastIndex`, `some`, `every`, `includes`, `indexOf`, `flatMap`, `flat`, `sort`, `toSorted`, `reverse`, `toReversed`, `slice`, `at`, `join`, `keys`, and `entries`. A callback can be an arrow or a function value. If the callback has a second parameter, it gets the index.

Each call becomes a loop in a function literal. No runtime package is necessary.

```go
const evens = nums.filter(n => n%2 == 0)

evens := func() []int {
	xs, f := nums, func(n int) bool { return n%2 == 0 }
	var out []int
	for _, x := range xs {
		if f(x) {
			out = append(out, x)
		}
	}
	return out
}()
```

- `reduce` needs an initial value: `nums.reduce((acc, n) => acc + float64(n), 0.0)`.
- `find`, `findLast`, and `at` return the element if it can be nil. Otherwise they return a pointer into the slice, or nil. An element of a type parameter can be nil only if each type in its constraint can be nil. So `find` on a `[]T` with `T any` returns `*T`.
- `findLast` and `findLastIndex` search from the end.
- `sort` and `reverse` change the slice in place, as in JavaScript. They also return the slice. As a statement, they become `slices.SortStableFunc`, `slices.Sort`, or `slices.Reverse`. `toSorted` and `toReversed` return a changed copy.
- The comparator of `sort` and `toSorted` returns an `int`, as in JavaScript: `users.sort((a, b) => a.Age - b.Age)`. The sort is stable. Without a comparator, the elements must be numbers or strings, and they sort in their natural order. JavaScript sorts them as strings.
- `slice(start, end)` returns a copy, as in JavaScript. `end` is optional. A negative index counts from the end. gosling clamps an index that is out of range. So `xs.slice(-2)` gives the last two elements.
- `at(i)` gives nil if `i` is out of range. A negative `i` counts from the end, so `xs.at(-1)` is the last element.
- `join(sep)` uses `strings.Join` for a `[]string`. For other elements, it uses `fmt.Fprint`.
- The callback of `flatMap` returns a slice. `flat` flattens one level. It becomes `slices.Concat(xs...)`.
- `keys` returns the indices. `entries` returns a `[]struct{ Index int; Value T }`.
- `forEach` can only be a statement.
- `filter` keeps a named slice type. A method of the type with the same name has priority.
- Each call in a chain is a separate loop.
- On an array, the result of `filter` is a slice. The loop uses `a[:]`, so `find` points into the array. If the array is not addressable, such as a function result, the loop uses a copy.

### Map methods

Maps have `has`, `get`, `keys`, `values`, `entries`, `delete`, and `forEach`:

```go
ages.has("ada")                                     // true if the key exists
ages.get("ada") ?? 0                                // the value, or 0 if the key is missing
ages.keys()                                         // []string
ages.values()                                       // []int
ages.entries()                                      // []struct{ Key string; Value int }
ages.delete("ada")                                  // delete(ages, "ada")
ages.forEach((age, name) => fmt.Println(name, age)) // the value comes first, then the key
```

- `get` returns the value if it can be nil. Otherwise it returns a pointer to a copy of the value, or nil if the key is missing. A write through this pointer does not change the map.
- The order of `keys`, `values`, `entries`, and `forEach` is random, as for `range`. `keys` does not sort. To sort the keys, assign them to a variable and call `slices.Sort`.
- `delete` and `forEach` can only be statements.
- A method of the map type with the same name has priority.

### Union types

```go
type Shape = Circle | Square | *Polygon
```

becomes:

```go
type Shape interface{ isShape() }

func (Circle) isShape()   {}
func (Square) isShape()   {}
func (*Polygon) isShape() {}
```

A type switch on `Shape` in a `.gol` file must list all variants or have a `default` case:

```go
switch const s = s.(type) {
case Circle:
case Square:
}
// error: switch on Shape is missing cases: *Polygon
```

- Variants must be types in the same package. They cannot be interfaces.
- Declare unions at package level, each with its own `type` keyword.
- `*Polygon` is a variant, but `Polygon` is not.
- `Circle` and `*Circle` can both be stored, but only `case Circle` counts.

### Struct shorthand and spread

```go
const u = User{name, age}    // User{name: name, age: age}
const all = [...a, x, ...b]  // slices.Concat(a, []int{x}, b)
const p2 = Point{...p, X: 5} // func() Point { v := p; v.X = 5; return v }()
```

- Shorthand applies only if a positional literal is not valid. So `Point{y, x}` sets `X` to `y`, as in Go.
- A slice spread always makes a new slice. It needs Go 1.22.
- In a struct spread, the spread comes first. Name all fields after it. For a pointer, write `...*p`.
- `&Point{...p, X: 5}` gives a pointer to the new value.

### Imports and generated names

gosling adds the imports that the output needs. If the package name is already in use in the file, gosling reports an error. If another file of the package declares the name, the import gets an alias, such as `fmtpkg`.

Some output must write a type, such as the result of `filter` or `??`. If a local declaration hides the name of that type, gosling reports an error. Rename the local declaration.

Error variables are `err`, `err2`, and so on. Labels are `catch_N`, `end_N`, `finally_N`, and `panic_N`. gosling does not use a name that the file already uses. Variables also do not use a name that the package declares at package level.

The output uses builtins such as `len`, `append`, `make`, and `nil`. If a declaration shadows a builtin where gosling needs it, gosling reports an error.

## Errors and line numbers

gosling type-checks each package. Errors show the line and column in the `.gol` file. With `-lines` (the default), the output has `/*line file.gol:N*/` comments. So compiler errors, `go vet`, and stack traces also show `.gol` lines.

## Limitations

- Without `catch panic`, a panic does not run `finally` blocks. A panic in a catch block or in a catch panic block also does not run them.
- `catch panic` cannot follow a typed catch clause.
- Object patterns have no rest element.
- `?.[index]`, `?.(call)`, and `??=` are not supported.
- In a try block, an optional call that returns an error is an error.
- Unions cannot be generic or be in a `type ( ... )` group.
- gosling does not check switches in `.go` files.
- In a `case` expression, a function type or literal cannot use `):`. Use Go order there.
- VS Code highlights the name in `name: type` parameters as a type.
- An arrow cannot get a type from the context if a local declaration hides the name of that type. Rename the local declaration.
- Only a package-level `const` with one name can hold a generic arrow. Go function literals cannot have type parameters.
- In a slice spread, untyped constants get their default type. Write `int64(1)`, not `1`, in `[...int64s, 1]`.
- gosling ignores build constraints in `.gol` files.

## How it works

1. `internal/preprocess` changes gosling syntax into valid Go and keeps all line numbers. For example, `try {` becomes `if true {`. Some syntax becomes calls to marker functions, such as `__goslingT` for templates.
2. `internal/transpile` parses and type-checks the result. It then uses the types to fill in arrow types, find calls to check, and replace array methods. It repeats until nothing changes.
3. Lowering records text edits on the source. It does not print the AST again, so comments and layout stay. gosling applies the edits, adds line directives, and runs gofmt.
4. `cmd/gosling` loads dependency types with `golang.org/x/tools/go/packages`. It processes directories in import order. Packages that import generated code type-check against the new output.
5. Emit also records a source map. The map pairs each token that the output copies from the `.gol` file with its new position. `internal/lsp` uses the map to send positions to gopls and to map the results back.

## Development

```sh
go test ./...                                         # all tests
go test ./internal/transpile -run TestGolden -update  # rewrite golden files
go test -short ./...                                  # skip tests that run the go tool
```

The language server tests run gopls. They skip if gopls is not installed or if you use `-short`.

To test the VS Code extension, run `npm test` in `editors/vscode`.

The CI workflow in `.github/workflows/ci.yml` runs on each push to `main` and on each pull request. It checks formatting, runs `go vet`, the Go tests, `gosling -check`, and the extension tests.

`internal/transpile/testdata/golden` has the expected outputs. Tests run `go vet` on each one. Tests build and run the programs in `internal/transpile/testdata/run`, and compare their output with the `.out` files.

### Releases

The release task needs [Task](https://taskfile.dev/). To make a release, run this command on an up-to-date `main`:

```sh
task release VERSION=0.3.0
```

The task tags the current commit as `v0.3.0` and pushes the tag. The version must be higher than the latest tag. The tag sets the version of the Go module and of the extension. Make a release for each change that you want users to get, also when only the Go code changes.

The release workflow in `.github/workflows/release.yml` sets the extension version from the tag. `package.json` keeps the placeholder version `0.0.0`, so a local build of the extension has version `0.0.0`. The workflow then builds `gosling.vsix`, creates the GitHub release, and attaches the file. The release becomes the latest release only after the workflow attaches the file. The install command in [Install the extension](#install-the-extension) always downloads from the latest release.

Do not create releases on the GitHub Releases page. A release that you publish there becomes the latest release before the workflow attaches `gosling.vsix`. During that time, the install command fails with a 404 error.

If the workflow fails, it changes the release for the tag to a draft. A draft is never the latest release, so the install command keeps the last good build.
